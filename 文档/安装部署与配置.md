# 安装部署与配置

## 1. 环境要求

实际 PHP 版本和扩展应与现有生产环境保持一致。最低部署检查项：

- Linux 或兼容的 Web 运行环境。
- Nginx/Apache，站点根目录指向 `public/`。
- PHP-FPM 及应用所需扩展。
- 与加密文件匹配的 ionCube Loader。
- MySQL/MariaDB。
- 对 `data/runtime/`、`uploads/`、`public/upload/` 等运行目录的写权限。

不要依据文档猜测版本并直接升级生产 PHP、数据库或 ionCube；先在隔离环境验证。

## 2. 获取代码

```bash
git clone https://github.com/2839273551/zjmfTheme.git
cd zjmfTheme/服务器源码
```

仓库不包含生产数据库凭据、运行缓存、用户上传和服务器备份。部署时这些内容必须从安全的运维渠道单独配置或恢复。

## 3. 数据库配置

复制示例文件：

```bash
cp app/config/database.example.php app/config/database.php
```

填写以下参数：

- `hostname`：数据库地址。
- `database`：数据库名。
- `username` / `password`：最小权限账户。
- `hostport`：数据库端口。
- `prefix`：现有数据表前缀。
- `authcode`：部署环境专用随机值，不能与示例或其他环境共用。
- `admin_application`：当前后台入口标识。

`app/config/database.php` 被 `.gitignore` 排除。任何真实值都不得写入提交、文档、Issue 或聊天记录。

## 4. Web 服务器

站点文档根目录必须指向：

```text
<部署目录>/服务器源码/public
```

服务器原有 `public/.user.ini` 含机器专用 `open_basedir`，因此不进入仓库。新环境应由运维按实际绝对路径配置，不要复制旧服务器路径。

应阻止 Web 直接访问 `app/`、`data/`、`vendor/` 和 Git 元数据。HTTPS、域名、伪静态和 PHP-FPM 参数沿用经过验证的生产配置。

## 5. 目录权限

运行用户需要写权限的目录通常包括：

```text
data/runtime/
uploads/
public/upload/
```

代码目录原则上只读。不要为解决权限问题将整个站点设为 `777`。生产部署后按实际 Web 用户设置所有者，并对普通代码文件使用最小权限。

## 6. 数据和上传文件

Git 仓库不承载：

- 生产数据库备份。
- 用户上传、证书、媒体和工单附件。
- 运行缓存、会话和临时文件。
- 服务器时间戳备份。

这些数据应通过加密备份、对象存储或受控文件同步恢复，并单独制定保留策略。

## 7. 启用主题

在系统后台分别选择：

```text
themes_templates = codex_framework
order_page_style = codex_framework
clientarea_default_themes = codex_framework
```

优先通过后台切换，不直接修改数据库。切换后清理应用和模板缓存，并检查：

- `/`
- `/cart`
- `/login`、`/register`、`/pwreset`
- `/clientarea`
- 服务列表、服务详情、购物车与结算链路

## 8. 缓存与基础验收

在部署目录执行与当前环境匹配的缓存清理命令；现有项目通常使用：

```bash
php think clear
```

验收底线：

- 页面和静态资源无 404。
- 手机、平板、桌面无横向溢出。
- 登录、注册、验证码和二次验证分支存在。
- 搜索、筛选、分页、续费、弹窗和批量操作有效。
- 服务端金额、库存、状态和权限未被前端覆盖。
- 未验证的产品类型不标记为完成。
