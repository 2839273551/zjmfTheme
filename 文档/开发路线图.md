# 开发路线图

> 本页整合自 2026-08-08 的两份重复项目进度表，并按 2026-08-21 的服务器源码基线重新归档。历史表中的状态只作为规划背景，实际状态以代码、GitHub 提交和真实环境验收为准。

## 1. 实施原则

- 先建立公共业务页规范，再完成服务核心闭环，随后扩展财务、工单、资料、安全和其他页面。
- 页面族使用不同但受控的视觉语言，避免全站重复同一种纹理。
- 所有视觉改造必须保留父主题 Hook、字段、AJAX、`$Nav`、动态侧栏和服务端金额/状态。
- 高风险控制、支付、密钥和认证流程必须先列出动作矩阵，再实施展示层改造。
- 每个页面族完成后同步积累桌面、平板、手机和异常状态回归基线。

### 2.1 代表性视觉边界

- 仪表盘：稀疏氛围光，不铺满装饰。
- 服务页：低对比技术网格、节点线或机柜刻度，集中于概览区域。
- 账单/交易：细纸纹和账本分隔线，金额与状态优先。
- 工单：轻量对话轨道和时间线，突出回复内容。
- 实名认证：证件线框、印章压纹和极淡防伪曲线。
- 安全页：微点阵和安全状态环，危险区保持纯色高对比。
- Cloud/DCIM/VNC 控制台：内容区保持纯净，避免装饰干扰操作。

### 2.2 关键验收点

- 服务列表变体不能因统一外壳遗漏产品专属操作。
- 普通详情的续费、升级、取消、日志、账单、下载和自定义字段保持有效。
- Cloud/DCIM 的电源、重装、VNC、网络、监控、密码和异步状态不可误触或丢失。
- 账单、交易和支付金额不得由前端重新计算。
- 安全页禁止恢复浏览器 AES；危险操作必须有确认和可理解反馈。
- 实名认证必须完整覆盖个人/企业、材料、审核中、失败原因和重新提交分支。

## 4. 推荐执行阶段

### 阶段 A：公共规范与服务核心

`CA-00 → CA-01 → CA-02 → CA-03`，并同步启动 `FP-09`、`FP-10`、`FP-15`。

### 阶段 B：高频业务闭环

并行推进 `CA-04`、`CA-05`、`CA-08`，随后完成 `CA-06`、`CA-07`。

### 阶段 C：购物与财务扩展

完成 `FP-01`～`FP-04`，再推进 `CA-09`～`CA-11`。

### 阶段 D：治理与收尾

完成 `CA-12`、官网内容、品牌定稿、主题预览图、自动化、可访问性、性能和发布演练。
