# 三端主题维护规范

本规范适用于 `web/`、`cart/`、`clientarea/` 三个 `codex_framework` 覆盖包。目标是让模板、样式和脚本保持可追踪、可回归，不通过不断追加覆盖规则解决问题。

## 修改前

1. 执行有超时的 `git fetch origin main`，比较 `HEAD`、`origin/main` 和 `git status`。网络失败时记录原因，只依据最后一次成功获取的基线。
2. 阅读根目录 `README.md`、本文件和目标端当前代码。工作区已有修改不得重置、覆盖或偷偷混入本轮提交。
3. 明确端归属和共享文件影响范围。`web/static/cart/` 同时影响 Web 与 Cart，变更后要核对两端版本和缓存。

## 模板契约

- 保留父主题 include、模板字段、Hook、表单 `action`、隐藏字段、`name`、`id`、`class`、`data-*` 和 AJAX 参数。确需修改 ID 时，先搜索全仓库引用并保证页面内唯一。
- 金额、库存、服务状态、权限和验证码结果只展示服务端结果。禁止在模板中用静态文案或固定颜色伪造业务状态。
- Cart 与 Client Area 继续依赖兼容的 `default` 父主题；不能把父主题文件复制进仓库，也不能假设父主题一定提供可选 JS 全局变量。
- 调用父主题变量或函数前使用 `typeof`、函数类型检查或等价保护。缺少可选能力时应保持默认流程可提交，而不是抛出 `ReferenceError`。

## CSS 规则

- 一个组件只保留一个主要规则源。不要在文件末尾追加第二套同名选择器覆盖前面规则；需要调整时直接修改原规则，或抽取有明确命名的变体。
- 状态使用语义 class（例如 `is-loading`、`is-error`、`is-warning`），由 JS 或服务端状态同步；不要使用脆弱的 DOM 结构猜测业务状态。
- 新增选择器前确认目标浏览器。除非在本文件和 README 声明最低版本，不使用 `:has()` 等会让整条规则在旧浏览器失效的选择器。
- 位移、阴影等 hover 动效放在 `@media (hover: hover)`；所有动画在 `prefers-reduced-motion: reduce` 下必须关闭。
- 删除旧页面后同步删除其专用 CSS 和媒体查询。保留仍被共享头尾使用的基础类，并用搜索结果证明引用关系。

## JavaScript 规则

- 模块初始化互相独立。一个可选节点不存在时只跳过该模块，不得用顶层 `return` 阻断后续功能。
- 事件绑定优先使用委托或带命名空间的绑定，避免 AJAX partial 重复绑定。异步流程必须同时处理成功、失败和完成状态，并同步 `aria-busy`、按钮禁用状态和可读错误信息。
- 页面过渡必须跳过当前 URL、下载链接、外部链接、带 target 的链接和显式禁用过渡的链接。
- Tab 控件必须成对提供唯一 `id`、`aria-controls`、`aria-labelledby`，并同步 `aria-selected`、`hidden` 和键盘方向键行为。
- 不在前端重新计算服务端金额、库存或权限；脚本只负责交互和状态呈现。

## 版本与缓存

- 端内模板、样式、脚本或资源发生变化时，同一提交更新该端 `VERSION`。
- 自有静态资源查询参数必须与端版本一致：Cart 使用 `?v=1.0.x`，Client Area 使用 `?v={$Ver}-1.0.x`，Web 使用 `?v=1.1.x`。
- 共享文件变更时提升所有实际受影响端版本，并在 README 记录原因。

## 提交前检查

在仓库根目录执行：

```text
pwsh -NoProfile -File scripts/validate-theme.ps1
git diff --check
git status --short
```

脚本会检查 CSS/JS 语法、差异空白、遗留选择器、调试输出、堆叠覆盖、旧首页类名和三端静态资源缓存参数。脚本通过后仍需逐项确认：

- `rg -n ":has\\(" web cart clientarea` 没有未评估的兼容选择器。
- `rg -n "Premium surface|override|TODO|FIXME|console\\.log|var_dump|print_r" web cart clientarea` 没有遗留堆叠覆盖或调试输出。
- 页面内 ID 唯一；Tab 的 ARIA 关联完整；移动端没有横向溢出或粘滞 hover。
- 三端 `VERSION`、模板资源查询参数和 README 版本表一致。
- 真实环境验证 `/`、`/cart`、可用商品配置页、`/clientarea`、登录、注册、找回密码、服务列表和服务详情。
- 验证 AJAX 成功、失败、取消和重试路径；确认金额、库存、状态、权限和验证码仍以服务端结果为准。

## 发布边界

只发布本轮实际变更文件。每个目标文件先备份，再逐文件上传、核对 SHA-256、清理缓存并记录版本、提交哈希、文件清单和验收结果。禁止整站覆盖、`rsync --delete`、远端递归删除和递归权限修改。
