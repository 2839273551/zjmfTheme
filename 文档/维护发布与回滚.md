# 维护、发布与回滚

## 1. 日常开发流程

1. 从 `main` 更新本地代码，确认工作区干净。
2. 明确本轮页面、真实 URL、产品类型和验收范围。
3. 阅读目标 `codex_framework` 文件及对应 `default` 父模板。
4. 列出必须保留的变量、字段、选择器、Hook、AJAX 和分流。
5. 优先实现页面外壳和专属样式，不接管服务端业务。
6. 本地检查模板标签、JS/PHP 语法、资源路径、CRLF 和响应式布局。
7. 提交前运行敏感信息和大文件检查。
8. 使用清晰提交信息，推送后以 GitHub 提交哈希作为发布基线。

## 2. 提交约定

建议提交信息：

```text
feat(theme): 完成用户中心服务列表布局
fix(auth): 保留验证码提交契约
docs: 更新部署与回滚流程
chore: 调整仓库忽略规则
```

一个提交只解决一个可描述的问题。不要把运行缓存、截图、压缩包、生产配置或无关格式化混入功能提交。

## 3. 发布前检查

- `git status` 只包含预期文件。
- 没有 `.env`、私钥、数据库配置、服务器路径、口令或令牌。
- 没有超过 GitHub 限制的文件。
- 主题 `theme.config` 保持 CRLF。
- 表单字段、Hook、AJAX、模板分支和父主题包含未被破坏。
- 认证与极验变更已覆盖普通 POST 和 AJAX 失败分支。
- 已记录待验证项，不用代码审查代替真实环境验证。

## 4. 远端发布

1. 在服务器为本轮目标文件建立带时间戳备份。
2. 将待发布文件上传至暂存目录。
3. 核对文件清单和哈希。
4. 逐文件安装，设置正确所有者和权限。
5. 清理应用与模板缓存。
6. 用真实域名、真实登录态和真实数据验证。
7. 验证桌面、平板、手机，以及空、错、权限不足和高风险操作状态。
8. 记录 GitHub 提交哈希、发布时间、文件清单和验收结论。

只发布本轮实际修改的文件，不用整个仓库覆盖生产站。

## 5. 回滚

出现业务契约异常、模板报错、资源 404、验证码失效或关键流程失败时：

1. 立即停止继续发布。
2. 从本轮时间戳备份恢复全部已覆盖文件。
3. 恢复所有者和权限。
4. 再次清理缓存。
5. 复核关键路由和文件哈希。
6. 记录失败原因、影响和后续修复计划。

失败发布不得标记为“已上线”或“已完成”。

## 6. 文档维护

- 当前事实只更新本仓库 `README.md` 和 `文档/`。
- 功能、配置、流程变化与代码在同一 Pull Request 或提交中更新。
- 动态发布记录应引用 GitHub 提交哈希。
- 本地独立文档、临时表格和截图不作为权威来源。
