# 项目架构与模板开发

## 1. 项目目标

项目在现有 IDC 售卖系统上维护一套独立主题，统一标识为 `codex_framework`，覆盖：

1. 官网（Web）。
2. 商品购买与购物车（Cart）。
3. 用户中心（Client Area）。

三端目录独立，但视觉、导航和业务跳转必须一致。旧主题继续保留，作为父主题、业务实现参考和紧急回滚基线。

## 2. 系统基础

- 应用版本：`3.7.6`。
- 框架：ThinkPHP/ThinkCMF 系列。
- Web 入口：`服务器源码/public/index.php`。
- CLI 入口：`服务器源码/think`。
- 部分控制器、路由和配置核心使用 ionCube 加密，不能仅凭源码推断所有运行逻辑。
- 业务正确性以可见模板契约、系统后台配置、真实数据和真实站点验收为准。

## 3. 三端主题结构

| 界面 | 主题目录 | 后台配置键 | 策略 |
| --- | --- | --- | --- |
| Web | `public/themes/web/codex_framework/` | `themes_templates` | 独立官网主题 |
| Cart | `public/themes/cart/codex_framework/` | `order_page_style` | 继承 `default` |
| Client Area | `public/themes/clientarea/codex_framework/` | `clientarea_default_themes` | 继承 `default` |

### 3.1 三端主题版本

Web、Cart 和 Client Area 分别在各自 `codex_framework/VERSION` 文件中维护独立的 SemVer 主题版本。`README.md` 中的 `3.7.6` 是应用版本，不得作为主题版本或静态资源缓存版本。

当前版本基线：

| 界面 | 版本文件 | 当前版本 |
| --- | --- | --- |
| Web | `public/themes/web/codex_framework/VERSION` | `1.0.0` |
| Cart | `public/themes/cart/codex_framework/VERSION` | `1.0.0` |
| Client Area | `public/themes/clientarea/codex_framework/VERSION` | `1.0.0` |

版本维护规则：

- 任一端的模板、样式、脚本或主题自有资源发生变更时，必须在同一提交中更新该端 `VERSION`；未变更的端不跟随提升。
- `MAJOR` 用于不兼容的模板契约或主题结构变化，`MINOR` 用于向后兼容的新页面或新能力，`PATCH` 用于兼容的修复、样式、可访问性和性能调整。
- 该端主题自有静态资源 URL 的缓存参数必须与 `VERSION` 一致；Client Area 可保留平台 `{$Ver}` 前缀，并在后缀使用主题版本，例如 `?v={$Ver}-1.0.1`。
- 父主题和第三方资源继续使用平台提供的 `{$Ver}`，不得为统一主题版本而修改 `default` 或第三方文件。
- 一个文件被多端复用时，修改该文件必须提升其所属端版本；若其他端也因该变化改变展示或行为，同时提升受影响端版本。

主要访问链路：

```text
Web /
  ├─ /cart
  ├─ /login、/register、/pwreset
  └─ /clientarea

Cart /cart
  ├─ configureproduct
  ├─ ordersummary
  ├─ viewcart
  └─ complete

Client Area /clientarea
  ├─ service、servicedetail
  ├─ billing、supporttickets
  └─ details、security、verified
```

## 4. 模板契约

模板采用 ThinkTemplate 风格语法，变量名区分大小写：

```tpl
{$Setting.company_name}
{if $Userinfo}...{/if}
{foreach $Cart.products as $list}...{/foreach}
{include file="themes/clientarea/default/service.tpl"}
```

必须遵守：

- Web 常见登录态变量为 `$userInfo`，Cart 和 Client Area 常见变量为 `$Userinfo`，不可擅自统一大小写。
- 静态资源优先使用同源 `/themes/...` 路径，并按三端主题版本规则保留 `{$Ver}` 或明确的缓存破除参数。
- `theme.config` 固定使用 CRLF；仓库已通过 `.gitattributes` 约束。
- 不得删除被 JavaScript 使用的 `id`、`class`、`name`、`data-*`、表单 action、隐藏字段或 AJAX 参数。
- 价格、库存、促销、订单摘要、服务状态和权限以服务端返回为准。

## 5. Cart 关键契约

商品配置页应继续复用父主题核心：

```tpl
{include file="themes/cart/default/configureproduct.tpl" /}
```

必须保留：

```text
#addCartForm.configoption_form
.configoption_total
#addToCartBtn
#addToCartBtnTwo
configoption[id]
customfield[id]
billingcycle
host
password
pid / currencyid / qty
```

价格刷新继续请求服务端 `ordersummary`，前端只负责加载状态和结果展示。

## 6. Client Area 关键契约

- 公共头尾保留 `client_area_head_output` 和 `client_area_footer_output` Hook。
- `$Nav` 继续负责动态多级侧栏。
- 服务详情必须保留 hosting、server、cloud、dcimcloud、dcim、software、cdn、other、ssl 等分支，以及模态框、升级和配置组件。
- 登录、注册、找回密码必须保留邮箱/手机分支、验证码、二次验证、自定义字段、服务条款、原始字段名与 action。
- 当前密码由服务端处理，禁止恢复浏览器 AES 或自行转换密码。

## 7. 极验插件

`public/plugins/addons/geetest_captcha/` 是 GT4 插件目录，插件配置存储于系统插件配置，不写入仓库。受保护页面包括登录、注册、找回密码和修改密码。

前端必须保留 GT4 四个字段：

```text
lot_number
captcha_output
pass_token
gen_time
```

修改密码链路还必须保留 `#modifyPwdForm`、`#modifyPwdSubmit`、`modifyPwdCheckForm()` 和 `/modify_password` AJAX 参数注入。

## 8. 修改边界

正常开发优先限定在三个 `codex_framework` 主题目录。只有明确任务需要时，才调整插件或父主题相关文件。

禁止修改：

- ionCube 加密控制器和路由核心。
- 数据库结构、订单数据和生产配置。
- `vendor/` 第三方实现。
- 未经验证的接口、变量、商品组 ID 和支付行为。
- SSH 私钥、数据库密码、API 密钥、VNC 密码或带令牌的 URL。
