# 安全与仓库管理

## 1. 仓库边界

仓库包含可复现的应用源码、依赖、主题、插件和维护文档，不包含生产秘密或运行数据。

明确排除：

- `服务器源码/app/config/database.php`
- `.env`、私钥、证书私钥、访问令牌
- `服务器源码/public/.user.ini`
- `服务器源码/data/runtime/`
- `服务器源码/.codex-backups/`
- `服务器源码/public/upload/`、`uploads/`、`downloads/` 的运行内容
- 旧源码副本、服务器压缩包、数据库备份和本地生成输出

## 2. 凭据管理

- 数据库密码、`authcode`、SSH 凭据和第三方 API Key 只存放于部署环境。
- 使用最小权限账户，测试、预发布和生产使用不同凭据。
- 不把凭据写入 Git 提交、文档、Issue、日志、截图或部署压缩包。
- 一旦秘密误入 Git，必须先轮换秘密，再清理 Git 历史；仅删除最新文件不够。

## 3. 提交前检查

至少检查：

```bash
git status --short
git diff --cached --stat
git diff --cached --name-only
```

重点搜索常见风险关键词，但避免在终端或工单中复制真实值：

```text
password, passwd, secret, token, private key,
access_key, authcode, database, hostname
```

第三方 SDK 中可能存在上述字段名或 PEM 解析代码，必须结合路径和值判断，不能把关键词命中直接等同于真实秘密。

## 4. 大文件和二进制

GitHub 单文件上限为 100 MB。用户上传、备份、视频和数据库转储不属于源码，应进入专用备份或对象存储。确需版本化的大型设计资产，应先评估 Git LFS。

## 5. 仓库权限

本项目含完整站点源码和商业/加密组件，应保持私有仓库，并只向实际维护人员授予访问权。不要在公开仓库、公开制品或公开日志中复制源码。

## 6. 权威来源

完成首次安全推送后：

- GitHub `main` 为代码和文档的唯一权威来源。
- 本地工作区是 GitHub 的受控检出，不是独立事实源。
- 独立文档副本在确认已合并、已推送、远端可访问后删除。
- 删除任何本地资料前必须先列出清单并获得明确确认。
